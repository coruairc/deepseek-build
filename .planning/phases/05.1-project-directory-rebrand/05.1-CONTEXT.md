# Phase 5.1: Project Directory Rebrand (INSERTED) - Context

**Gathered:** 2026-11-26
**Status:** Ready for planning

<domain>
## Phase Boundary

The rebrand stopped at the home directory: `~/.deepseek-build` was branded, but every
project-scoped lookup still hardcoded `.grok`. This phase makes the project directory
`.deepseek`, keeps `.grok` as a compatibility fallback so repositories written for
grok-build remain usable, and leaves a single constant that the open-build variant flips
to `.ob`.

**Out of scope:** the home directory (`~/.deepseek-build`), `~/.grok` user-level legacy
reads, `.grok-snapshots`, session storage, `rewind-checkpoints`, the `.grok-plugin/`
marketplace index convention, and any crate or package rename (decision D2).

</domain>

<decisions>
## Implementation Decisions

### One constant, one fallback list
- `xai-grok-brand::PROJECT_DIR_NAME = ".deepseek"` and
  `LEGACY_PROJECT_DIR_NAMES = [".grok"]`, with `.deepseek` first everywhere. — **Reversibility:** costly — the name is user-visible in every project-scoped path; the open-build variant changes exactly this constant to `.ob`.

### Surfaces
- Agents, plugins, skills, workflows, project `config.toml`, hooks, `lsp.json`, sandbox
  profiles and `workspaced.toml` all resolve through the constant, with `.grok` as a
  lower-priority fallback and `.claude`/`.cursor`/`.agents` keeping their existing
  relative order.

### Compatibility
- A repository with **only** `.grok/` keeps working: discovery, skills and project config
  are proven by dedicated tests. When both exist, `.deepseek` wins for the same name.
- `workspaced.toml` is read from both and written to `.deepseek`; an existing `.grok`
  file is never migrated or rewritten.

### Residuals (recorded, not changed)
- `cwd/.grok/rewind-checkpoints` stays where it is: it is per-session durability storage,
  and splitting the mirror across two directories could silently stop rehydrating
  existing sessions' blobs.
- `.grok-plugin/` is a marketplace index convention, not the project config directory.

</decisions>
