status line (`StatusLineItem::Cost`), rendered by
`crates/codegen/xai-grok-pager/src/views/status_line/segments.rs`. Everything else in Phase 1

## Cost Segment Contract

The segment is a single, self-describing string. It is built once in `compose_builtin` and is not
post-processed by anything except the row's existing whole-line elision.

### Format rules

| Rule | Contract |
|------|----------|
| Frame | `~` + `$` + number + one ASCII space + `est.` |
| Below one cent | exactly **4** decimal places: `~$0.0042 est.` |
| At or above one cent | exactly **2** decimal places: `~$0.37 est.` |
| Branch selection | 4 dp is used only when the value **rounds to less than $0.01 at 4 dp**; a value that rounds up to a full cent (for example `0.00996`) therefore renders `~$0.01 est.`, never `~$0.0100 est.` |
| Rounding | standard decimal rounding at the last displayed place; ties are not load-bearing (no example below sits on one), and the `~` and `est.` markers carry the imprecision |
| Trailing zeros | kept — precision is fixed per branch, so the segment does not jitter in width as the number moves |
| Separators | no thousands separators, no space around `$` or the decimal point, always `.` (no locale) |
| Floor | hidden below **$0.0001**, the smallest value 4 dp can show as non-zero. The floor is derived from the precision, not tuned. |
| Non-finite / negative | omitted, exactly like absent — never `~$NaN est.` |
| Magnitude suffixes | none. No `k`, `M`, `thousand`, or rounding of the integer part. |

Contractual values (names are illustrative; the values are not):

| Name | Value |
|------|-------|
| `MIN_DISPLAYED_COST_USD` | `0.0001` |
| sub-cent precision | `4` |
| cent-and-above precision | `2` |
| promotion threshold | `0.01` after 4-dp rounding |
| estimate prefix | `~` (U+007E) |
| estimate label | `" est."` (leading space, trailing period, lowercase) |

### Rendered states

| Input | Rendered text | Painted columns |
|-------|---------------|-----------------|
| `None` (unreported, ledger unreadable) | *(segment omitted)* | 0 |
| `0.0` | *(segment omitted)* | 0 |
| `0.00004` | *(segment omitted — below floor)* | 0 |
| `0.0001` | `~$0.0001 est.` | 13 |
| `0.0042` | `~$0.0042 est.` | 13 |
| `0.0099` | `~$0.0099 est.` | 13 |
| `0.00996` | `~$0.01 est.` | 11 |
| `0.01` | `~$0.01 est.` | 11 |
| `0.3745` | `~$0.37 est.` | 11 |
| `1.006` | `~$1.01 est.` | 11 |
| `12.34` | `~$12.34 est.` | 12 |
| `1234.5` | `~$1234.50 est.` | 14 |

### Width envelope

- Painted width is **11–13 columns** for every value in `[$0.0001, $999.99]`.
- The widest ordinary render is **13 columns** (`~$0.0042 est.`, `~$999.99 est.`), versus a 5–8
  column range today. There is no cap: above `$999.99` it grows by one column per extra integer
  digit, and the number is never abbreviated, rounded, or pre-truncated — the row's elision handles
  the overflow. No separator, padding, row, or terminal column is added; the row still occupies the
  same one line of the same width, and the user's other items lose only the columns this segment's
  extra text consumes.
- The segment is **not** passed through `fit_columns`; it has no per-segment budget.

### What this phase must not do to the segment

- No second segment. Splitting into `~$0.37` + `est.` would put a ` │ ` separator inside the figure.
- No wrapping, no second line, no growth of `StatusLineDisplay::line_count` beyond `1`.
- No colour, weight, or modifier change (see Color).
- No `≈` (U+2248), `∼` (U+223C), full-width tilde, `EST`, `Est.`, or the word `estimated` — the
  decision fixes `~` and `est.`, and non-ASCII substitutes break the one-column-per-character math.

## Spacing Scale

A terminal row is measured in painted **columns**, not pixels; the template's 4-px scale does not
apply. Declared values:

| Token | Value | Usage |
|-------|-------|-------|
| label-gap | 1 column | the single U+0020 inside ` est.` |
| segment-gap | 3 columns | `SEGMENT_SEPARATOR` (` │ `) between items — unchanged |
| row-padding | 0–16 columns per side | the existing `padding` config key, default `0`, capped at 16 — unchanged |
| min-row-width | 1 column | below this the row paints nothing (`inner_width`) — unchanged |

Exceptions: none. No new spacing token, no extra space around `~` or `$`, and no re-ordering of the
user's `items`.

## Typography

There is one type size in a TUI: the terminal's cell. The contract is therefore glyph width and
tone, not point size.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Row text (cost included) | 1 cell | normal, `theme.muted()` | 1 terminal row |
| Separator | 1 cell | normal, `theme.dim()` | 1 terminal row |
| Warning (not used by cost) | 1 cell | normal, `fg(theme.warning)` | 1 terminal row |

- Every character in the cost string (`~ $ . e s t` and digits and the space) is width-1 in every
  terminal font; painted width equals character count. Keep it ASCII so this stays true.
- No bold, italic, underline, reverse, or blink on the cost segment.
- The row is always exactly one line; a terminal row has no leading.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg_base` = `BG_STORM` `#161714` | the status-line band, painted by `render_status_line` |
| Secondary (30%) | `gray` = `COMMENT` `#75715e` via `theme.muted()` | all built-in segment text, cost included |
| Accent (10%) | `warning` = `YELLOW` `#e6db74` | `context` at the compaction threshold, and nothing else |
| Destructive | `accent_error` = `PINK` `#f92672` | not used in this phase |
| Separator | `gray_dim` `#5a584c` via `theme.dim()` | ` │ ` between segments only |

Accent reserved for: the `context` segment at its threshold. **The cost segment must not use the
accent, warning, or error colour, and must not gain a threshold tint at any value** — an estimated
cost is not an error, and a colour change would be a new interaction contract this phase has not
earned.

No new theme token, no new hex value, no new style helper. Segment tone stays `SegmentTone::Dim`,
which resolves through the existing quantisation path (256-colour, 16-colour, `NO_COLOR`).

## UI Considerations

Applicable state considerations resolved: 2 covered, 0 backstop, 0 unresolved.

The only element in this phase is a single `static-content` label, so the relevance filter raises
only `overflow` and `long-text`. `empty` / `loading` / `error` / `partial` / `populated` /
`zero-one-many` apply to form, list, nav, media and control kinds — none of which exist here. The
segment's absent state is a `static-content` omission, and it is specified in the Copywriting
Contract above rather than restated.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| overflow | `cost` segment | ✅ covered | The row is one line and never wraps (`line_count() == 1`); overflow is the existing right-edge `…` elision. `~` then `$` precede the digits, so any cut of ≥2 columns still reads as an estimate. |
| long-text | `cost` segment | ✅ covered | Width is bounded at 11–13 columns for `[$0.0001, $999.99]`; above that it grows one column per integer digit and elision handles it. No magnitude suffix, no internal truncation of the number. |

## Interaction Contract

| Behaviour | Contract |
|-----------|----------|
| Visibility | The segment appears when the value is at or above `$0.0001` and disappears when it is absent, unknown, or below the floor. Appearance/disappearance changes no other item. |
| Layout stability | The built-in row reserves exactly one line whenever `type = "builtin"` resolves, so the segment coming and going never reflows the transcript. This phase must not change that. |
| Update cadence | Unchanged. The row rebuilds at turn end, session start, model or effort switch, and on the existing 300 ms debounce. It repaints continuously through a turn only when `tokens`, `cache`, or `turn-timer` is also in `items` (`StatusLineItem::varies_mid_turn`). **Do not add `Cost` to `varies_mid_turn`** — that would repaint the whole row every tick for a figure that moves only when usage lands. |
| Model switch | The figure re-prices on the next rebuild from the new model id (existing `fill_estimated_cost` behaviour). No new state. |
| Precedence | A provider-reported cost still wins over the table. The label is applied to whatever the segment renders, so the marker never implies "table-derived". |
| Configuration | `[ui.status_line.pricing]` is read at startup, so a pricing edit applies at the next launch. This phase does not add a live reload. |
| Interactivity | None. The segment is not focusable, not clickable, has no OSC 8 link, and has no tooltip. `compose_builtin` returns no link spans for `Segments`, and it must stay that way. |
| Screens | The row is hidden on the welcome screen and under a fullscreen subagent, as today. No cost-specific exception. |
| Cross-surface number | For the same usage and the same `[ui.status_line.pricing]`, the TUI figure and headless `estimated_cost_usd` must be equal **before formatting**. The rendering differs on purpose: TUI `~$0.37 est.`, JSON `0.3745…` + `"estimate": true`. Do not format the JSON field into the TUI string or vice versa. |
