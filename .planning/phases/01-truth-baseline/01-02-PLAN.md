<objective>
Make `scripts/sandbox-run.sh` tell the truth about IPv6: resolve the allow host over both families,
allow an allowlisted IPv6 destination, and report a refused IPv6 destination by address instead of
`non-ip` (SBOX-02, second half). Prove it offline with a checked-in harness.

Purpose: the provider is reached over an IPv6 NAT64 address on the author's network. Today the shim
resolves only A records, allows only `::1`, and prints `non-ip` for every IPv6 refusal — so an operator
reading the egress audit cannot tell which destination was refused. That is an audit-truth defect in the
same family as the rest of this phase.

Output: an extracted C shim that handles both families, one shared address representation for the
allowlist, a blocked line that always names the destination, an offline six-assertion harness, and the
coupled prose updates that would otherwise contradict the code.

Execution shape: one implementer, one working tree. `depends_on: 01-01` serialises the mandated order;
no artifact of 01-01 is used. Do not commit.

Tooling note: this host has `shellcheck`, `cc`, `python3` and `flock`, but **not** `dash`. Use `sh -n`
for the POSIX harness and `bash -n` for `sandbox-run.sh` (it is a bash script with `pipefail`), never
`dash -n`. `/bin/sh` is bash here, but do not rely on that: invoke the bash script with `bash`.
</objective>

    `hints.ai_socktype = SOCK_STREAM`; do not set `AI_ADDRCONFIG` (it would hide AAAA answers on a host

    add the mapped forms — an `AF_INET6` address that is v4-mapped (`::ffff:a.b.c.d`) is compared as the
    4-byte IPv4 address against the allowlist and against the loopback rules. An IPv6 allowlist entry must
    be permitted on an IPv6 connect.

    The blocked report keeps the exact prefix the existing parsers expect
    (`sandbox-run: BLOCKED connect to <destination>`) and now formats per family with
    `inet_ntop(AF_INET6, …, INET6_ADDRSTRLEN)`; the literal `non-ip` survives only for a genuinely

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process `connect()` -> shim | every outbound socket in the sandboxed run passes through this interposer; a miss becomes real egress |
| DNS answer -> allowlist | the resolver's answer decides what is reachable, so a family the shim ignores is either blocked too broadly or allowed too broadly |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05 | Tampering | IPv6 allowlist matching | medium | mitigate | Compare family plus raw address bytes, never formatted strings; v4-mapped addresses are normalised to their 4-byte form so one entry cannot be bypassed by a mapped spelling. |
| T-01-06 | Information disclosure | blocked-destination report | low | accept | The line names an IP address the process already tried to reach; no payload, no credentials. |
| T-01-07 | Repudiation | harness proving a private copy of the shim | medium | mitigate | The harness compiles the tracked `scripts/egress_guard.c`, and assertion 6 runs the real `scripts/sandbox-run.sh` end to end with `BIN=/bin/echo` and `DEEPSEEK_BUILD_EGRESS_HOST=localhost`, so no lookup leaves the host. |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No dependency or tool is installed; the harness uses only `cc`, `python3` and the shell already on the host. |
