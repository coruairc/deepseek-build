<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| formula text -> a user's machine | a mutable URL or a missing hash turns a package install into an unverified download |
| in-tree formula -> a public tap repo | publication is an author action; this phase must not create a public repo |
| release `SHA256SUMS` -> the formula | a hash transcribed from a local build would pin a different artifact than the release serves |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-09 | Tampering | formula URL/sha256 pinning | high | mitigate | Both URLs must be the exact `github.com/.../download/v0.1.0-proof1/...` asset paths (https, no other host) and both hashes must appear in the release's own `SHA256SUMS`; no source-build stanza, no `head`, no `patch`. |
| T-04-10 | Spoofing | a formula that installs something other than the release binary | medium | mitigate | The checker requires `bin.install "deepseek-build"`, the `dsb` symlink, `doc.install` of the licence files and a `--version` test; the optional online check matches `Content-Length` to the release asset size. |
| T-04-11 | Repudiation | a doc that implies a live tap or a successful `brew install` | medium | mitigate | The doc states the tap repo does not exist and no `brew` ran; the evidence records text-level and URL-level checks only; no `ruby`/`brew` is installed to fake a result. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | Python stdlib checker + text edits; no Ruby gem, no Homebrew, no package manifest change. |
</threat_model>
