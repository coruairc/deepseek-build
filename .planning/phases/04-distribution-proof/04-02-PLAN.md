<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub release -> local install | downloaded bytes are executed as a binary; only the checksum chain stands between the asset and the user |
| release asset -> working tree | the published installer must be provably this source, or the proof certifies different code |
| README prose -> user action | a stale or optimistic sentence sends a user to a URL that 404s |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Tampering | downloaded tarball / installer asset | high | mitigate | Checksum verified before extraction by `install.sh` itself, then independently re-derived by the proof and compared against `SHA256SUMS` and GitHub's asset `digest`; the installer asset is compared byte-for-byte to the working tree. |
| T-04-06 | Spoofing | the proof silently using the loopback fake tree | high | mitigate | `prove-install.sh` never sets `DSB_INSTALL_BASE_URL` or the `DSB_INSTALL_TEST_UNAME_*` hooks; the URL is printed and asserted to be `github.com`; the fake-tree suite is named only as an unchanged unit check. |
| T-04-07 | Repudiation | README claiming an install path that does not work | medium | mitigate | The unpinned status codes and the installer's real failure line are recorded, and `check-readme-distribution.py` requires the 404 truth in the prose; the negative assertions reject the stale claims after whitespace normalization. |
| T-04-08 | Elevation of privilege | installer writing outside the scratch directory | low | mitigate | Every run uses `HOME` and `INSTALL_DIR` inside `mktemp -d`; `install.sh` is unchanged and needs no sudo; the trap removes the scratch tree. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | POSIX sh + Python stdlib; nothing installed; `gh` and `curl` already present. |
</threat_model>
