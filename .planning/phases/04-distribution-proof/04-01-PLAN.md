<objective>
Push exactly one throwaway pre-release tag — `v0.1.0-proof1`, tag-only, never `main` — and prove what it
produced: a green five-job release run with the container job present, both macOS legs inside their
budget, the release classified as a pre-release with exactly the six expected assets, the four tarballs
intact and checksum-consistent with GitHub's own asset digests, and `:latest` untouched.

Purpose: this is the only real tag the milestone pushes. Everything after it (installer proof, Homebrew
hashes, registry proof) consumes its assets, and Phase 3's REL-02/REL-03 macOS claims are closed by the
same run. The tag run is also the first live evidence of the Phase 3 split, so its failure modes must be
caught here rather than after a second, accidental tag.

Output: `scripts/distribution-proof.py` (a daemonless harness with an offline fixture mode), the pre-push
GHCR baseline, the tag-push record, and the run/release evidence with the release's own `SHA256SUMS`.

Execution shape: one implementer, one working tree, one network action (the tag push) preceded by a
recorded dry run, then a bounded wait on the CI run. The four tarballs are downloaded to a temp dir and
never committed. No `main` push, no `--tags` push, no `gh workflow run`, no Docker daemon.
</objective>
