<objective>
Make the permission prompt honest and prove it: the high-signal warning must actually paint (today it is dropped
for exactly the execute prompts it exists for), and both headless denial lines must name both flags so an
unattended user is told how to proceed.

Purpose: PERM-01 and PERM-02 are the items the author leans on every day. Both are broken in this tree for
reasons the research already located: `build_permission_display` rebuilds the title for execute prompts and
throws the ACP title (with its `⚠ Security warning:` prefix) away, and the final denial string was written before
the `--permission-mode auto` path existed. Both are minimal in-scope product fixes under CONTEXT's defect policy.

Output: two product fixes with tests, one new pty scenario, one new headless integration target, one committed
evidence item, one refreshed `scripts/test-gate.expected`.

Execution shape: **build host**. Rust 1.94.0 pinned, >=150 GB free, shared `CARGO_TARGET_DIR`, a release binary
built after each product fix, and `PAGER_BINARY` pointing at a **private copy** of that binary (see the context
block: 02-01 is also wave 1 and builds the same artifact). No key and no network: the pty harness and the
headless runner both drive the real binary against a loopback mock.

Scope note: this plan deliberately covers only PERM-01 and PERM-02. Permission-mode visibility across a resume
(PERM-03), headless plan arming (PERM-04) and the plan-mode read-only property (SESS-02) live in 02-06 — they
touch the shell's plan-mode gate and the mode-chip surface, and bundling them here pushed the plan to 1.5x the
smart-zone budget with three unrelated subsystems in one context window.
</objective>
