committed artifacts carry no key material, and the author has revoked the key — and record the revocation as the
attestation it actually is.

real endpoint with a fake key and expects a 401, so it is not a no-network step. Task 2's checkpoint is a human
action on platform.deepseek.com; the rest of Task 2 needs only `grep` and `git`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live key -> artifacts and logs | the key is compromised-by-policy; any appearance in a committed file is unrecoverable |
| author's word -> evidence item | the revocation cannot be verified by any tool; the item must not present it as verified |
| scan path set -> the claim "the tree is clean" | a scan that silently skips paths (or fails open) certifies nothing |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-07 | Information disclosure | key material reaching a committed cast, log or note | high | mitigate | Canary run proves the product writes no key; `--scan` over `docs/evidence` and over every phase-touched path must exit 0 before the item is sealed; the note is itself scanned and hashed; the key is never used as a grep pattern (argv is world-readable). |
| T-02-08 | Repudiation | an attestation presented as a verified revocation | high | mitigate | The item carries the author's dated sentence, a sentence saying no API exists to check it, and a grep step that proves only the sentence's presence; `notes.md` states the limit in the same paragraph. |
| T-02-09 | Tampering | a scan that fails open, or a path set that omits the items | medium | mitigate | The gate is `--scan`, which fails closed on grep rc>=2; the path set is derived from `git diff --name-only` plus `git status --short`, so a new file cannot be missed; `IN-07` is quoted rather than ignored. |
| T-02-SC | Tampering | dependency / package installs | high | mitigate | No dependency is added: the plan uses the existing `scripts/key-leak-check.sh`, `git`, `grep` and `python3`. Any new dependency or outbound destination is stop-and-ask. |
