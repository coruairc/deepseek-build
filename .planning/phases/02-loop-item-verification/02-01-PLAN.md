## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| author's shell environment -> captured pty | the key lives in the environment; `script(1)` records everything the pty writes, including echoed input |
| live provider -> committed artifact | provider output (including any echoed header or error body) crosses into a file that will be committed |
| evidence recorder -> reviewer | `report.json` is the only artifact a reviewer reads; if it can overstate, the whole phase is worthless |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information disclosure | `script -T` capture of the live session | high | mitigate | Key exported in the parent shell before `script`, never inside the capture, never `set -x`; `scripts/key-leak-check.sh --scan` over the item must exit 0 *before* `finish` and before any commit; `evidence.py normalize` rewrites `<REPO>/<HOME>/<TMP>` so no absolute home path is committed. |
| T-02-02 | Repudiation | `report.json` claiming a pass that did not happen | high | mitigate | Every step is a real `grep -F` over a committed file recorded by `evidence.py step`; `finish --result ok` refuses a failed or zero-step record; `report.json` is never hand-edited (a correction is a new directory per the convention). |
| T-02-03 | Tampering | a step needle weakened so a failed run also matches | medium | mitigate | Needles are the script's own printed sentences (`8 passed, 0 failed`, `web_fetch made a real connection to`); the task forbids replacing a needle with a generic word, and `notes.md` records the real printed line. |
| T-02-SC | Tampering | dependency / package installs | high | mitigate | No dependency, tool or package is added by this plan: the scripts, `python3`, `git`, `cc` and `script(1)` are already required by the tree. Any new dependency or outbound destination is stop-and-ask (D6/D10/D13). |
</threat_model>
