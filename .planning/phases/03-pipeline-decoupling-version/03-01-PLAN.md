<objective>
Decouple the release graph so a slow macOS leg can no longer erase the container image, and put the
`docker/metadata-action` tag list behind a guard that fails loudly before the first push
(REL-01, REL-08).

Purpose: today one `build` job runs all four legs and both `publish` and `container` need it, so the
`v0.0.1-rc4` `aarch64-apple-darwin` timeout (run `40111152104`) skipped the image entirely. The split
alone fixes the coupling; the guard closes the second silent path, where a non-semver `v*` tag makes
`type=ref,event=tag` emit `:v0.1` **and `:latest`**, the push succeeds, and only the final
`imagetools inspect` fails after `:latest` has already moved.

Output: `release.yml` with `build-linux`/`build-macos` and the three `needs` edges, a strict semver
check in the `version` job, `scripts/guard-image-tags.sh` plus its fixture suite wired before the first
push, `scripts/check-release-workflow.py` asserting the whole graph, and README entries.

Execution shape: one implementer, one working tree, no cargo, no network, no CI dispatch. The workflow
edits are pushed untested by decision (CONTEXT: "No separate CI proof run"); the first real evidence is
Phase 4's tag run, so every assertion this plan can make statically it must make statically.
</objective>

## Review revisions (mandatory — from the plan-checker, 2026-11-26)

These amend the task contract above; where they conflict, these win.

1. **Stable guard must require the aliases.** For a stable version the guard requires, each exactly once,
   all five names: `<version>`, `v<version>`, `<major>.<minor>`, `<major>`, `latest`. Missing either
   alias is a failure. Add fixtures `stable-missing-minor` and `stable-missing-major` that must exit
   non-zero, in addition to the existing cases.
2. **Prerelease set is exactly two names.** For a prerelease the only permitted names are `<version>` and
   `v<version>`; `latest`, `<major>.<minor>` and `<major>` must all be absent, each asserted. (The pinned
   metadata-action collapses the semver aliases to the full prerelease string, so two is correct.)
3. **Reject build metadata.** The `version` job's semver gate accepts `X.Y.Z` and `X.Y.Z-<prerelease>`
   only. A tag containing `+` (e.g. `v0.1.0+build.5`) must fail with a named `::error::` before any
   build, because the pinned metadata-action sanitizes `+` to `-` and the guard would otherwise compare
   mismatched names after `publish` has already created a release.
4. **Record the major-alias decision.** `{{major}}` resolving to `0` for `v0.1.0` is ACCEPTED and
   published (`ghcr.io/...:0`), not suppressed. Do not add an `enable=` conditional. State this in the
   plan SUMMARY and in the guard's header comment.
