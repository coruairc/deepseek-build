<objective>
Settle the tag shape before any tag is pushed: verify that `v0.1.0` traverses the trigger, the version parse,
the prerelease classification, the release gate and `install.sh`'s validation exactly as a stable release
must, and that the shapes which would classify wrongly (`v0.1`, `v1`, `v0.1.0.0`) are rejected before
anything is built (PKG-03).

Purpose: a dry run is a real push. Every fact this phase can prove about the tag shape has to be proven
before Phase 4 creates a throwaway tag, otherwise the first evidence is a registry write. The parse and the
classification are shell inside the workflow, so they can be extracted and executed here; the installer's
URL construction can be exercised against the loopback fake tree; the rest is asserted from the parsed YAML.

Output: `scripts/check-release-tag-shape.py` (trigger, extracted derive fixtures, release gating),
`scripts/check-release-pipeline.sh` (the single static gate), a stable `0.1.0` section in
`scripts/test-install.sh`, and README entries. `install.sh` is read and exercised, not rewritten.

Execution shape: no cargo, no network beyond `127.0.0.1`, no CI dispatch, no tag. `python3` + PyYAML,
`actionlint`, `shellcheck` and `sh` are the whole toolchain. One implementer, one working tree.
</objective>
